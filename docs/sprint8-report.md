# Sprint 8 — informe de implementación y validación

El segundo prompt rige la implementación: inferencia local con Ollama, sin API de IA pagada. Este informe registra lo observado en la laptop de validación. Los datos G&V son simulados para demostración.

1. **Archivos creados.** `backend/app/agents/` (agente, cliente LLM, registro, ejecutor, schemas, prompt y cinco módulos de herramientas), `backend/app/api/routes/analyst.py`, `backend/app/schemas/analyst.py`, `backend/app/services/analyst_service.py`, `backend/scripts/test_analyst_local.py`, `backend/tests/fakes.py`, `backend/tests/test_analyst_agent.py`, `backend/tests/test_analyst_api.py`, `backend/tests/test_analyst_tools.py`, `frontend/src/pages/AnalystPage.tsx`, `frontend/src/types/analyst.ts`, `docs/analyst-agent.md`, `docs/integrity-sprint8-baseline.json` y este informe.
2. **Archivos modificados.** `.env.example`, `README.md`, `docker-compose.yml`, `backend/requirements.txt`, `backend/app/api/router.py`, `backend/app/core/config.py`, `backend/app/core/exceptions.py`, `backend/app/main.py`, `backend/app/repositories/deviation_repository.py`, `backend/app/services/deviation_service.py`, `frontend/src/app/App.tsx`, `frontend/src/app/router/routes.ts`, `frontend/src/pages/CaseDetailPage.tsx` y `frontend/src/services/api.ts`. La ampliación del repositorio de desviaciones solo cuenta casos distintos por tipo; no cambia la detección.
3. **Versión de Ollama.** Imagen Docker `ollama/ollama:0.34.4`.
4. **Modelo local utilizado.** `qwen2.5:3b` en esta laptop; `qwen2.5:7b` permanece como valor predeterminado configurable del repositorio.
5. **Tamaño descargado.** Aproximadamente 1.9 GB para 3B y 4.7 GB para 7B. Ambos se descargaron; el volumen persistente `ollama_data` conserva los modelos entre reconstrucciones.
6. **Configuración utilizada.** Valores predeterminados: Ollama interno, seis rondas, diez mensajes de historial, 60 s por petición LLM, 50 elementos por resultado y temperatura 0.1. El `.env` local, excluido de Git, cambió únicamente `OLLAMA_MODEL=qwen2.5:3b` y `ANALYST_TIMEOUT_SECONDS=180` para esta máquina.
7. **Arquitectura del agente.** React → FastAPI → `ProcessAnalystAgent` → `OllamaLLMClient` → Ollama. El agente ejecuta herramientas a través de `ToolRegistry`, `ToolExecutor` y servicios/repositorios existentes. Existe un solo agente.
8. **Herramientas.** `get_case`, `get_case_timeline`, `get_case_conformance`, `get_case_deviations`, `get_case_prediction`, `get_case_alerts`, `get_process_summary`, `get_process_variants`, `get_process_transitions`, `get_deviation_summary` y `get_alert_summary`.
9. **Esquemas de entrada.** Pydantic estricto: `EmptyInput`, `CaseCodeInput`, `CaseListInput`, `VariantListInput` y `TransitionListInput`; se prohíben campos adicionales, tipos incorrectos y códigos de caso vacíos.
10. **Tool loop.** El modelo solicita una herramienta, el backend valida nombre y argumentos, ejecuta un servicio de lectura, devuelve JSON como mensaje de tool y consulta de nuevo al modelo.
11. **Límites.** Seis rondas máximas, historial de diez mensajes, entradas de 2.000 caracteres, topes por tool y timeout configurable. El loop termina con respuesta controlada si alcanza el límite.
12. **Errores.** Nombre desconocido, JSON mal formado, argumentos inválidos, resultado vacío, timeout y servicio caído se controlan. No se ejecuta una herramienta alternativa arbitrariamente ni se presenta como hecho una respuesta sin consulta satisfactoria.
13. **Read-only.** Solo se registran las once consultas. No hay tools de SQL, shell, web, escritura de alertas, entrenamiento, importación ni creación de predicciones. Tampoco hay RAG.
14. **Evidence.** Se deriva exclusivamente de resultados de herramientas ejecutadas en FastAPI; nunca la genera Ollama. La API también expone traza de nombre, estado y tiempo, sin razonamiento interno.
15. **Status.** `GET /api/v1/analyst/status` indica enabled, configured, provider, model, available y read_only. Devolvió `available: true` con 3B; al detener Ollama devolvió `false` mientras `/health` y Process Mining siguieron respondiendo.
16. **Chat.** `POST /api/v1/analyst/chat` recibe message, history y context_case_code; devuelve answer, provider, model, read_only, tool_calls, evidence, duración y rondas.
17. **Pantalla.** `/analyst`, “Analista IA”, integrada al diseño G&V. Muestra estado, modelo local, consulta, actividad de herramientas, evidencia y tiempo.
18. **Contexto de caso.** `/analyst?case=...` orienta las preguntas. El código no sustituye la consulta por tool.
19. **Preguntas sugeridas.** Seis tarjetas, incluyendo variantes, transición, retrabajo y preguntas de caso; el detalle del caso enlaza a `/analyst` como acción secundaria. “Nueva conversación” limpia solo memoria React.
20. **Variante real.** `LEAD → CONTACTED → QUALIFIED → VISIT → RESERVED → CONTRACT`: 224 casos, 55.86 %.
21. **Transición real.** `LEAD → CONTACTED`: mayor duración promedio, 2.1 días según el formato devuelto por el backend.
22. **Desviaciones reales.** `DEMO-00089`: cuatro registros: `SLA_BREACH` en LEAD; `REWORK` y `BACKTRACK` en QUALIFIED; `REWORK` en VISIT. Además, 79 casos distintos tienen `REWORK`.
23. **DEMO-00141 real.** Predicción persistida con score 0.999705 y nivel `HIGH` (riesgo estimado alto, no probabilidad calibrada); alerta `ALR-000001` con estado `RESOLVED`.
24. **Tools de cada ejemplo.** Variante → `get_process_variants`; transición → `get_process_transitions`; retrabajo → `get_deviation_summary`; desviaciones de `DEMO-00089` → `get_case_deviations`; riesgo de `DEMO-00141` → `get_case_prediction`; alerta de `DEMO-00141` → `get_case_alerts`. Todas completaron una ronda y una tool exitosa.
25. **Tiempo observado.** Respectivamente 48.4 s, 15.8 s, 8.6 s, 41.9 s, 37.3 s y 24.5 s en CPU con 3B precargado. Una consulta de riesgo en frío tardó 165.7 s; la interfaz espera hasta 300 s para permitir esa carga y una posible corrección de tool call.
26. **Tests nuevos.** Unitarios e integración API con `FakeLLMClient` cubren registro, las once tools, validación estricta, multi-ronda, límite, evidencia, respuestas sin tool, no encontrado, lenguaje predictivo, grounding y estado de Ollama no disponible.
27. **Total pytest.** 108 tests pasaron, con cinco advertencias de dependencias existentes, sin Ollama real.
28. **npm build.** `npm run build` finalizó correctamente; Vite advirtió que un chunk supera 500 kB.
29. **Docker.** Base de datos, backend, frontend y Ollama saludables. `docker compose config --quiet` pasó. Backend y frontend se reconstruyeron; el backend no depende del estado de Ollama.
30. **Alembic.** `alembic check`: `No new upgrade operations detected.` No hay migración Sprint 8.
31. **Events.** 2.209 registros; SHA-256 `d4d3ffc3834edc68074ebdf7377862cdab9a6bc62acf598ede883c382d84ffe0`, idéntico al baseline.
32. **Deviations.** 883 registros; SHA-256 `fa3efe22c38727a3440776a4dbdaea19599432c3b9a6a1124d70d6145b3630cb`, idéntico al baseline.
33. **Modelo ML.** Versión activa `next-deviation-v1-20260920T152325973583Z-da48007b`; SHA-256 del artefacto `f59a0df6024a2d7c561ab917c652ec4d0f64d1451a070c232871304fa3cf5ca9`, idénticos al baseline. No se reentrenó.
34. **API pagada.** No hay API key ni proveedor de inferencia pagado. El módulo no requiere una API de inferencia pagada y funciona sin costo por llamada a API; hardware y electricidad sí tienen costo.
35. **Demo offline.** La arquitectura solo usa modelo, servicios y datos locales; imagen y modelos ya están descargados. La preparación está detallada en `docs/analyst-agent.md`. No se realizó una prueba física desconectando Internet durante la validación.
36. **RAM observada.** Ollama con 3B consumió aproximadamente 2.22 GiB de un límite Docker/WSL de 3.505 GiB. El 7B descargado no completó su primera carga dentro de 60 s bajo ese límite.
37. **Limitaciones reales.** Inferencia CPU lenta y variable; tool calling de 3B puede producir parámetros o texto inconsistentes. Se incorporaron validación, fallback y respuestas determinísticas para consultas demostrativas sensibles a cifras. Para mayor calidad, usar 7B/8B en un equipo con memoria suficiente; no se requiere GPU.
38. **Criterios de aceptación.** Cumplidos los criterios funcionales y de regresión del segundo prompt: proveedor local, configuración, un agente, once tools de lectura, endpoints, UI, tests offline, Docker, Alembic e integridad protegida. La capacidad offline está preparada por diseño y descargas previas, pero no se verificó mediante desconexión física. No se implementó Sprint 9, notificaciones ni modificaciones de alertas.
